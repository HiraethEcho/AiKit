# Submission Guide — AI4Math Intensive YSDA 2026

课程参与者通过 OpenReview 平台准备和提交论文的指南。

---

## 流程概览

课程以完整的科学出版周期结束：

1. **摘要** — 任务和方法的简要描述。
2. **完整论文** — 包含结果和形式化的完整工作。
3. **双盲评审** — 每位参与者评审 3 篇论文。
4. **作者回复** — 作者对评审意见的回应。
5. **最终展示** — 评审结果优秀的工作在结课会议上展示。

## 摘要要求（截止：5月1日）

- **标题** 论文标题。
- **摘要**：150–300 字。描述任务、方法和预期结果。
- **关键词**：3–5 个用于评审者匹配的术语。
- 通过 OpenReview 的 submission 表单提交。

摘要用于 bidding 阶段——评审者据此表明哪些论文他们有兴趣且有能力评审。

---

## 论文要求（截止：5月5日）

**格式：**
- PDF，4–8 页（不含参考文献列表）。
- 模板：课程标准 LaTeX 模板（将发布）或满足结构的自由格式。

**必需章节：**

1. **Introduction** — 问题陈述和动机。
2. **Related Work** — 文献综述（建议使用 AI4Math 的 `web_search` + `pdf_download` + `pdf_read`）。
3. **Methodology / Approach** — 方法描述、使用的工具、形式化。
4. **Results** — 实验结果和/或形式化证明。如果使用了 `lean_check`，请提供 Lean 代码和验证状态。
5. **Conclusion** — 结论和未来工作方向。
6. **AI Disclosure** — 写作中使用了哪些 AI 工具（AI4Math、ChatGPT、Claude、Copilot 等），用于哪些任务，如何验证其输出。

**双盲：** 不要注明姓名、所属机构，也不要在可识别的上下文中引用自己以前的工作。

## 评审（5月5–12日）

每位参与者评审 **3 篇论文**。评审者分配通过 OpenReview solver 基于 bidding preferences 自动完成。

**评审表格：**

1. **Summary** — 3–5 句 *用自己的话*（不是从摘要复制）。
2. **Strengths** — 至少 2 个优点。
3. **Weaknesses** — 至少 2 个缺点或问题。
4. **Questions for Authors** — 1–5 个问题，作者将在作者回复阶段回答。
5. **评分**（1–5 分制）：
   - Soundness — 结果和证明的正确性。
   - Clarity — 表达质量。
   - Novelty — 方法的原创性。
   - Overall — 总体评价。
   - Confidence — 您对评审的信心程度。
6. **AI Disclosure** — *Was any AI assistant used to write this review? If yes — describe.* 诚实回答是必须的。这不是惩罚，而是课程主题的一部分。

**决定（PC 根据评审结果给出）：**

| 类别 | 含义 |
|---|---|
| **Distinction** | 杰出工作，在最终展示中展示 |
| **Solid** | 高质量工作，满足课程要求 |
| **Revise** | 需要修改（评审中的具体建议） |

我们有意避免 Accept/Reject 格式——这是练习，不是竞赛。

---

## 作者回复（5月12–15日）

评审公开后，作者可以：
- 回答评审者的问题（通过 OpenReview 文本回复）。
- 上传修改后的论文版本（可选）。

作者回复是科学过程的重要部分。针对具体意见回答，不要争论评分，而是解决具体问题。

## 最终展示（5月16日）

获得 **Distinction** 的工作在结课会议上展示（10–15 分钟报告 + 5 分钟提问）。

形式：线下展示或视频会议。

## 隐私

- Submissions 和 reviews 仅对作者、指定评审者和 PC 可见。
- 评分和评审不公开发布。
- 工作公开披露——由作者在课程结束后自行决定。

---

## Matching 作为课程练习

将 50 位评审者 × 3 篇评审的分配作为优化问题在课堂上讨论：

- **随机分配** — baseline。
- **基于 affinity 的贪心算法** — O(n²)，提高质量但不最优。
- **匈牙利算法 / min-cost flow** — 最优解。
- **OpenReview solver** — 内置工具，作为比较的参考点之一。

学生在自己 bids 的真实数据上比较这些方法。
