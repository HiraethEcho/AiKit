# SOURCES — 搜学习资源

阶段二。产出物：`reference/README.md` 的资源索引 + `reference/` 下的只读副本。

## 顺序

1. 问偏好
2. 找本地
3. 搜网络
4. 写索引

不许跳过第 1 步直接搜。学生手边就有 `~/Public/minimind-dlm` 时，网上第一篇博客反而是噪声。

## 1. 问偏好

一次问完，多选题：

```
你想从哪类资源入手？（可多选，也可以指定具体的一本/一门/一个仓库）
1 书 / 教材        2 课程（视频或讲义）   3 论文
4 代码库 / 开源实现  5 文档 / 官方 reference  6 博客 / 教程
```

再问一句：**「有没有你已经信得过的来源，或者已经排除了的？」** 排除项同样要记 —— 写进索引的备注列，避免下次又搜出来。

## 2. 找本地

按顺序看：

| 位置 | 找什么 |
|---|---|
| 当前目录 `reference/` | 已有副本和索引 |
| `~/Public/` | 参考仓库原文（如 `~/Public/minimind`、`~/Public/lean-toric`） |
| `~/Projects/` | 自己或别人已经改过的版本 |
| 学生的 `memo.md` / `README.md` | 他自己列过的参考 |

本地命中优先于网络。命中后照第 4 步「副本策略」处理。

## 3. 搜网络

- 一次搜一个知识点，不要「帮我找 XX 的学习资料」这种大词。
- `web_search` 之后**读原文再写进索引**。只看到标题就写推荐，等于编。
- 一条资源要能回答三个问题才算合格：**覆盖哪个知识点 / 为什么选它而不是别的 / 用它做什么题**。答不上第三个就丢掉。
- 记录发布或更新年份。版本敏感的学科（框架、编译器、API）里过期的教程比没有更糟。

## 4. 副本策略

| 资源类型 | 怎么放 |
|---|---|
| 代码库 | 复制到 `reference/<name>/`，跳过 `.git`、`.lake`、`build`、`.venv`、`node_modules` |
| 论文 / 书 | 存链接和出处，不存 PDF。要存就放 `/mnt/extra` 并软链 |
| 视频 / 课程 | 只存链接 + 大纲摘要 |
| 大文件（数据、权重、工具链） | 软链到 `/mnt/extra`，`.gitignore` 里排除 |

`reference/` 对学生是**只读**的：上游副本原样保留，不在里面改。要改就在 `reference/examples/` 写自己的版本，并注明差异（见第 6 节）。

## 5. 写索引

写进 `reference/README.md`：

```markdown
# reference

| 名称 | 类型 | 位置 / URL | 覆盖知识点 | 为什么选它 | 对应练习 |
|---|---|---|---|---|---|
| minimind | 代码库 | ~/Public/minimind | AR 预训练最小实现 | 单文件可读，无框架魔改 | exercise/01-*.py |
| dllm 论文 | 论文 | https://arxiv.org/abs/xxxx | A2D 的目标函数 | 原始定义，别处都是转述 | exercise/05-*.md |
```

「对应练习」列不许空。资源不落到某道题上就只是收藏夹，不是学习材料。

## 6. 提取例题（进 `reference/examples/`）

`reference/examples/` 是例题与答案的落点，agent 写全。来源两种：从 `reference/` 的上游副本提取，或自己出题。

`exercise/` 里习题的解答另写一份到 `reference/solutions/NN-topic.<ext>`，序号与 `exercise/` 对齐。两者不合并：`reference/examples/` 是自读材料兼基准，`reference/solutions/` 是对拍基准，验收前不给学生看。

1. **标注来源。** 文件头写 `source: reference/<name>/<file>:<line>`，自己出的写「出自本 SKILL」。
2. **只留例题需要的那部分。** 不要把整个函数搬过来；删掉与例题无关的分支和依赖。
3. **改写的地方显式说明。** 简化过、换了变量名、去了一层抽象 —— 写在文件头的「与 reference 的差异」。
4. **一个文件一道题。** 先题面，再 `## 解答`，放同一个文件。
5. **索引写进 `reference/examples/README.md`**：题号 / 知识点 / 来源 / 对应的 exercise 文件 / 对应的 solutions 文件。
6. **同步生成辅语言对照版。** 主语言之外的口头指定语言（如 C++）也在 `reference/examples/` 里生成一份，
   **注释写厚** —— 它不用于做题，只用于自读。重点写那门语言有、主语言没有的坑
   （整数溢出、无符号下溢、取整方向、值传参变拷贝、不做边界检查）。
   它**不镜像到 `exercise/`**，是读物不是作业。索引里单列一行，注明「不镜像，自读」。

`reference/` 仍然只读。要改就在 `reference/examples/` 写自己的版本，然后注明差异。

## 7. 收尾

1. `reference/README.md` 写完
2. 把「这个学科的主要路线」用一张小表说清：先学哪个、依赖哪个，像 `lean/LEARN.md` 的学习顺序那样
3. 告诉学生下一步读 `SCAFFOLD.md`
4. 索引超过 10 条时，按知识点分组重排一次，不要平铺
5. `reference/examples/` 与 `reference/solutions/` 的索引表要能回答「这道题的基准数从哪来」—— 对拍时靠它

## 反模式

| 做法 | 后果 |
|---|---|
| 不先问偏好，直接给「Top 10 教程」 | 学生已排除的类型又被端上来 |
| 资源只列链接不写用途 | 一周后没人知道为什么收藏它 |
| 把整篇文档内容抄进 `reference/` | 索引变噪声，真正要看的表被埋掉 |
| 不记版本和年份 | 框架大版本变了以后，学的是旧 API |
| 把 reference 整段搬进 `reference/examples/` | 学生照抄 reference 就行，不是在自己推导 |
| 辅语言版只给代码不给注释 | 学生看不懂为什么这么写，对照就失去意义 |
| 辅语言版也镜像到 `exercise/` | 做题清单翻倍，每天题量失控 |
| 一次搜十个主题 | 每条都只有标题，质量等同没有 |
