# ASK — 问清楚我要学什么

阶段一。产出物只有一件：**写进 `README.md` 的「学习契约」**。契约没确认，不要碰 `SOURCES.md`。

## 为什么先问

「教我 PyTorch」和「教我读懂 transformers 的 attention 实现以便改它」是两份不同的工作：前者三个月，后者一周。用户说出的是他习惯的说法，不是他要的东西。等 directory 建完再发现错，返工成本全在学生身上。

## 怎么问

一次一问。每题带自己的猜测和置信度，让学生回「对/不对/改一下」比让他从零组织答案快。

```
HYPOTHESIS: <一句话说我猜你要什么>
CONFIDENCE: ~40% — 还缺：<未解决的点>

Q: <一个问题>
GUESS: <你的猜测 + 产生它的理由>
```

规则：

- **能自己查的事实不要问。** 目录里有什么、环境里装了什么、系统 `python` 是哪个 —— 去看。决策才问。
- 置信度低于 ~70% 时，同一行补一句「还缺什么」。这个数字是给自己看的，写高了后面会露馅。
- 置信度连续三轮没涨 → 停，说明问题问错了，重述一遍并换个角度。
- 学生答「随便你定」不等于确认，给两个具体选项让他选。

## 必问的六项

| # | 问题 | 不好与好的答案 |
|---|---|---|
| 1 | **学什么**，具体到能检验 | ✗「学 DLM」 ✓「能自己写 A2D 那 300 行，并和 AR baseline 对拍」 |
| 2 | **为什么现在学** | 决定深度：为改代码、为读论文、为面试，三条路深浅不同 |
| 3 | **现在什么水平** | 让他指一个已经会的东西当标尺，别问「你熟不熟」 |
| 4 | **怎么算学会** | 必须是可跑的验收：跑出某个数、通过某个 check、能给别人讲清某个机制 |
| 5 | **明确不学什么** | 一半的错位来自没说清 non-goals |
| 6 | **节奏** | 一次多久、多久一次。决定题目切多大 |

## 停止条件

能预测学生接下来三个问题会怎么答 —— 就到了。这是可检验的门槛，不是感觉。

问了几轮还是答不上「他的反应会是什么」→ 停，说：「我问了 N 轮还是猜不准，缺的是地基性的东西，要不要退一步重述？」不要继续磨。

## 产出模板

写进 `README.md`：

```markdown
## 学什么

- 目标：<一句话，可检验>
- 为什么：<一句话>
- 起点：<已经会什么>
- 怎么算学会：<可跑的验收条件>
- 不学什么：<明确的 non-goals>
- 节奏：<一次多久 / 多久一次>

## memo

<学生的原话，不要改写。以后回看这个文件时，要能看到他当时是怎么说的。>
```

`memo` 段保留原话。改写过的目标日后会看不出偏差。

## 反模式

| 做法 | 后果 |
|---|---|
| 一次问五个问题 | 学生挑简单的答，难的那个被静默丢掉 |
| 问「你想学到什么程度」 | 学生答「熟练」——不可检验，等于没问 |
| 接受「大概」「了解就好」 | 验收条件永远定不下来，后面每轮都要重问 |
| 自己替学生决定深度 | 三周后他说「我要的只是读懂」，工作区全废 |
| 学生给了「最佳实践式」的答案就通过 | 那是他以为该说的，不是他要的。追问：如果不必向任何人交代，你实际想要什么？ |
| 没确认就开建目录 | 契约之外的每一行都是返工 |

## 收尾

契约确认后：

1. 写入 `README.md`（`## 学什么` + `## memo`）
2. 告诉学生下一步读 `SOURCES.md`
3. 如果学生没确认，停在这里等；不要替他确认
