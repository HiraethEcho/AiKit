# NOTES — 把问答落成笔记

阶段四。在四步中都生效，不停留在最后。

## 何时写

三个触发点，任一命中就写：

1. **一个知识点答完** → 立刻沉淀，不等学生提醒
2. **学生说「记一下」/「存起来」** → 立即写
3. **一轮结束前** → 查这次对话有没有还没落盘的结论，补上

写之前先判目录，判错了整份笔记都要搬家。

## 判目录

问两个问题：

| 问题 | 是 | 否 |
|---|---|---|
| 换一台机器这句话还成立吗？ | `notes/` | 下一题 |
| 是程序吐的还是人写的？ | `logs/run/` | `logs/dev/` |

| 目标 | 内容 | git |
|---|---|---|
| `notes/` | 概念、原理、架构、坑、约定 | tracked |
| `logs/dev/` | 本机实测数字、环境状态、文件清单、踩过的坑、失败尝试 | tracked |
| `logs/run/` | 训练日志、`metrics.csv`、`summary.json`、曲线图 | ignored |

边界的常见误判：

- 「本机 torch 2.12 的 matmul 精度是 1.2e-4」→ 数字是本机的，但结论「fp32 下误差量级 1e-4 属正常」是通用。写 `notes/`，把数字放进 `logs/dev/` 并互相引用。
- 「这个包的 API 从 5.x 起签名变了」→ 通用，`notes/`。
- 「装 dllm 时 transformers 被顶到 5.x」→ 本机事件，`logs/dev/`。
- 「例题本身」不进 `notes/`。例题与解答归 `reference/examples/` 与 `reference/solutions/`；例题暴露出的知识点才写 `notes/`。

## 文件命名

```
notes/README.md         一行说明这个目录收什么
notes/01-topic.md       编号 + kebab 主题
notes/02-topic.md
logs/dev/01-local-state.md   固定：环境 + 当前进度
logs/dev/02-topic.md
```

- 编号两位，顺序即阅读顺序。
- 同一主题的补充**合进原文件**，不要开 `03-topic-fix.md`。一份文件只留一个真相。
- `notes/README.md` 里维护一行索引：编号 / 主题 / 一句话。

## 笔记结构

```markdown
# <主题>

<一句话结论。读完这句就该知道这篇讲什么。>

## <小节>

| 列 | 列 |
|---|---|
| ... | ... |

```<lang>
// 只在能省掉一段解释时才贴代码。贴最小的那段。
```

## 坑

1. <现象> → <原因> → <怎么办>

## 来源

- <URL>
- `path/to/file.py:123`
```

只写实测或注明来源的数字。不写「据说」「大概」「应该可以」。外部结论给出处，URL 或 `file:line` 二选一。

## 风格规则

继承 `ARnDlm/AGENTS.md` 的写作要求：

1. **简洁、准确、紧凑。** 不写过渡句，不铺垫，不重复上一个小节。
2. **表格和代码块优先。** 能进表格的不要写成段落。
3. **只写实测或注明来源的数字。** 没测过的写「未实测」。
4. **旧笔记有错就改掉**，不在旁边加一条纠正。
5. **概念、坑、约定用编号列表**（3 条以上时）。
6. **术语统一**：一个概念只用一个词，不要同义词轮换。首次出现的领域术语给一句定义。
7. **不加「总结」段**。开头那句结论就是总结。

## 风格优化循环

这是本文件存在的第二个理由：规则本身也要迭代。

触发条件 —— 出现任一条就回头改上面的「风格规则」：

- 同一处措辞或结构在 **≥3 篇笔记**里重复出现 → 提成规则，写进来
- 某条规则被违反 **≥2 次** → 规则写得不够具体，改成可判定的写法（给正例和反例）
- 某条规则从没被用到 **且明显没人会违反** → 删掉。规则越多越没人读
- 学生指出「这条我读不懂」→ 改的是规则，不是那一篇笔记

改完在 `logs/dev/` 记一行：改了什么、为什么、改了哪条。历史要可追。

## 进度

例题写在 `reference/examples/NN-topic`，题面写在 `exercise/NN-topic`，解答写在 `reference/solutions/NN-topic`，三边序号对齐，对拍靠 `reference/examples/README.md` 的索引。

每轮结束更新 `logs/dev/01-local-state.md` 的「当前进度」段：

```markdown
## 当前进度

- 最近完成：exercise/03-*.py 通过 check.sh
- 卡在哪：A2D 的 mask 对齐，见 notes/04-*.md
- 下一步：exercise/04-*.py
```

不写情绪，只写状态。下次开新会话时，这份文件是第一份要读的。

## 反模式

| 做法 | 后果 |
|---|---|
| 把概念解释写进 `logs/dev/` | 换机器后这份记录失去意义，真正要看的人找不到 |
| 把本机路径和版本号写进 `notes/` | 三个月后过时，读者以为是通用结论 |
| 一个知识点的补充开了三个文件 | 读者不知道哪份是对的 |
| 长篇散文，没有表格 | 复习时要重读一遍才知道讲了什么 |
| 记「训练好像变快了」 | 不是数字，无法复查 |
| 对话里说了结论但没落盘 | 会话一结束就没了 —— 这就是本 SKILL 存在的原因 |
