# 启动提示词（可直接复制）

从 2026-10-01 那次长程任务（ARnDlm 实验版 10 格）提炼。`{}` 替换掉，其余原样发送。

三条硬规则，任何版本都要带：

1. **最终确认闸门** — 问完所有问题后停下，等一句明确的「开始」再动手。
2. **总是问截止时间** — 没有截止时间也要明确说「没有」。
3. **总是问截止时间的两条分支** — 到点时「已完成」怎么办、「未完成」怎么办，分开回答。

## 最小版

> 持续进行直到完成计划，期间自主决策。
>
> 遇到难以解决的问题，如果无法在合理时间内解决，可以先记录问题，继续进行其他任务，
> 之后再回头解决。确保每个阶段的任务都能按计划推进。
>
> 每个阶段（每个 milestone，那 10 格项目）都要做如下子任务：
> - 先保证代码无 bug，通过测试。
> - 然后检查代码质量
> - 迭代 2-3 次。保证代码无 bug，简洁，高质量。
> - 加细对应步骤的教学计划
>
> 每一项子任务完成后都做 commit 存档。
>
> 再确认一遍完全清楚我的要求，不清楚的地方再问我。
>
> 然后问我这三个问题，等我全部回答完再继续：
> 1. 截止时间是什么？给我日期、时间、时区。没有截止时间就说「没有」。
> 2. 到了截止时间，任务已经完成，怎么办？
> 3. 到了截止时间，任务还没完成，怎么办？
>
> **问完先停下，等我最终确认后再开始执行任务。** 我没有明确说「开始」之前，
> 不要动手，也不要先写第一行任务代码。

> 不清楚的地方问我，直到确信可以一口气完成全部任务。
> **这里产出的 checkpoint 模型加上 `-example` 后缀来区分正式版。**

> 之后再回头解决。确保每个阶段的任务都能按计划推进。

> 每个阶段（每个 milestone，那 10 格项目）都要做如下子任务：

## 为什么这么写

| 段 | 作用 | 不写会怎样 |
|---|---|---|
| **「问到我确信能一口气完成」** | 把不确定性前置到零成本时刻 | 3 小时做在错误的矩阵上 |
| **「自主决策」+「难问题记录后继续」** | 授权范围 + 防止单点阻塞 | 一个 bug 卡住全部；或反过来什么都来问 |
| **四子任务循环** | 每个 milestone 走同一条机械路径 | 后半程质量衰减，第 9 格不如第 1 格 |
| **「等我最终确认后再开始」** | 显式启动闸门 | 边确认边动手，确认完已经改了一半 |
| **「总是问截止时间」** | 把时间盒提前定死 | 干到一半用户说「我半小时后要结果」，只能乱收尾 |
| **「问已完成/未完成两条分支」** | 到点时的行为提前商定 | 到点无人决定：要么硬停丢进度，要么超时硬跑 |

## 那次实际发生的事（当反面教材看）

| 提示词缺失 | 后果 |
|---|---|
| 没要求先确认 | 行3 十格里有 3 格**从没加载预训练权重**，LoRA 挂在随机底座上，所有数字看起来都合理 |
| 没要求检查「对拍是否可能假通过」 | C5 的值比对是**死代码**（load 完再比，比的是刚写的值和它自己） |
| 没提计时要预热 | decode benchmark 无预热，报 745 ms（实际 49 ms），差点得出「我们的采样器慢 15 倍」的错误结论 |
| 没要求 upsert 保护规范行 | 一次 6 步调试跑**覆盖了 RESULTS 里的 200 步正式行**，直到下次全量跑才碰巧盖回来 |
| 没要求长跑用 subagent 监督 | 长进程可能失联，无人回报 |
