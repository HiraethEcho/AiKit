# Math Conjecture–Proof–Research Loop

## Overview

The fundamental research cycle: conjecture, prove, verify, record. Every attempt — successful or not — is logged with numbered prefixes so nothing is lost and reading order is clear.

## When to Use

- Proposing new mathematical statements
- Attempting proofs (successful or not)
- Recording stuck points and partial results
- Running multiple proof attempts on the same conjecture
- Synthesizing results from failed attempts into new approaches

## Accepts

- `rounds`: number of proof attempts to run (default: 3, max: 20)
- `output_dir`: directory for attempt files (default: `mimo-attempt/`)

## Workflow

```
1. FORMULATE  → State the conjecture precisely
2. ATTEMPT    → Write proof for N rounds, recording each
3. VERIFY     → Check each proof for gaps
4. RECORD     → Write numbered files: conjecture, attempts, results
5. SYNTHESIZE → If stuck, extract useful lemmas and restart
```

---

## Stage 1: Formulate

A well-formed conjecture:
- **Hypotheses:** Every assumption explicit (singularities, rank, dimension, Picard number)
- **Conclusion:** One clear claim
- **Sharpness:** Example showing the bound is attained
- **Depends on:** Prior results it relies on

**Template:**
```
Conjecture X (Name). Let [objects] satisfy [hypotheses]. Then [conclusion].

Sharpness: [example]. Depends on: [result list].
```

## Stage 2: Attempt (N rounds)

Each round produces a file with prefix `NN-` for reading order.

### File naming convention

```
output_dir/
  01-conjecture.md          # The precise statement
  02-first-attempt.md       # Round 1: initial proof
  03-round-2-fix.md         # Round 2: fix gaps from round 1
  04-round-3-fix.md         # Round 3: fix gaps from round 2
  ...
  NN-stuck-summary.md       # Final: what worked, what didn't
```

Prefixes enforce reading order: `01` is the conjecture, `02`–`NN` are attempts in sequence, the final file summarizes. `00-summary.md` is generated by `math-summary` and sits at the top.

### What to record in each attempt file

```markdown
# Attempt [N] — [date]

## Proof attempt

[Full proof text, step by step]

## Verification

| Step | Claim | Status | Issue |
|------|-------|--------|-------|
| 1    | ...   | ✓/✗    | ...   |

## Useful lemmas discovered

- **Lemma A:** [statement] — not enough for this round, but might help later
- **Lemma B:** [computation] — correct but doesn't close the proof

## Intermediate results

- **Proposition C:** [statement] — proven, but weaker than needed
- **Claim D:** [statement] — false, counterexample: [example]

## Stuck points

- **Stuck 1:** [description of where the proof breaks]
  - Tried: [approach that didn't work]
  - Why it fails: [root cause]
  - Possible way forward: [idea for next round]

## What changed from round [N-1]

- Fixed: [what was wrong before]
- New issue: [what appeared after the fix]
```

## Stage 3: Verify Each Proof

After writing a proof, check every step:

### Stress tests for claims

| Claim type | Test |
|------------|------|
| **Dimension count** | Is $\dim(\text{sweep}) = \dim F + \dim(\text{family}) - \dim(\text{base})$ correct? |
| **Inequality** | Direction correct? Strict vs non-strict? |
| **Citation** | Hypotheses of cited theorem match your setting? |
| **Generality** | Works for all points or only general points? |
| **Existence** | Proven or assumed? |
| **Splitting** | Is the claimed bundle splitting valid? (Only $\mathcal{O}(2) \oplus \mathcal{O}^{n-1}$ if normal bundle is trivial) |

### Common gap patterns

| Gap | Symptom | Fix |
|-----|---------|-----|
| Wrong singularity class | Using smooth-specific result on singular variety | Check if result extends |
| Missing cone theorem | "By the cone theorem..." without verifying existence | State dependency explicitly |
| Off-by-one | Family dimension estimate inconsistent | Recount carefully |
| Circular reasoning | Step depends on conclusion | Restructure the argument |
| Too strong a claim | Proving $A$ when you need $A'$ (weaker) | Weaken the intermediate claim |

## Stage 4: Record

After each round, write the attempt file. After all rounds, write the summary.

### Summary template (final file)

```markdown
# Research Summary — [Conjecture name]

## Rounds completed: [N]

## Conjecture status: [Proven / Open / Disproven / Partially proven]

## What was proven

- **Lemma 1:** [statement] — proven in round [X]
- **Proposition 1:** [statement] — proven in round [Y], useful for [Z]

## What failed and why

- **Attempt 1:** [approach] — failed because [reason]
- **Attempt 2:** [approach] — failed because [reason]

## Stuck points (unresolved)

1. [description] — tried [approaches], root cause: [analysis]
2. [description] — tried [approaches], root cause: [analysis]

## Possible directions forward

1. [idea] — would require [new tool/theorem]
2. [idea] — related to [known result]

## Reading order

00-summary.md → 01-conjecture.md → 02-first-attempt.md → ... → NN-stuck-summary.md
```

## Stage 5: Synthesize (if stuck)

When stuck after N rounds:
1. Extract all useful lemmas from failed attempts
2. Identify the **exact point** where every attempt breaks
3. Check if a different prior result could bypass the stuck point
4. If yes: start a new round with the different approach
5. If no: record the stuck point as an open problem

**Lemma extraction rule:** Every intermediate result that is TRUE but insufficient for the main conjecture should be recorded as a named lemma. These may be useful for:
- Other conjectures in the same project
- Weaker versions of the main conjecture
- Future work by others
